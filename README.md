# 值班交接体系

一张交接单、一份风险清单，解决一个很具体的问题：**交接班的时候，信息丢了。**

没有代码，没有需要安装的东西。打开 Excel 就能用。

---

## 为什么做这个

我在一份 7×24 值班的岗位上待了一年多。这一年里经历过几次 P1 级故障，其中一次网络中断让我印象最深——不是因为它多严重，而是因为**我作为现场的人，看到的全是症状，看不到病因**。

我知道连接数归零了，但不知道是哪条链路断了；我知道告警在刷屏，但不知道主备链路已经同时失效。这些信息，是我事后从别的岗位问来的。

后来复盘才想明白：问题不在某个人的能力，而在**信息在交接时断层了**。

值班的人站在"症状层"，而"病因层"的信息分散在网络、系统、厂商等其他岗位手里——**交接班是这两层之间唯一的桥**。桥断了，症状层的人就只能靠猜和问。

这张表，就是把桥修起来。

## 怎么用

1. 打开 Excel，先看 **「使用说明」** 和 **「示例」** 两页（3 分钟）
2. 复制 **「交接单」** 页，每次交接填一份，约 2 分钟
3. 填不完就先填三栏：**未闭环事件、临时规避措施、未知项**

Excel 里有五个工作表：使用说明 / 交接单 / 示例 / 交接记录 / 风险清单。

其中两块最容易被忽略、后果也最严重：

- **【四】临时规避措施** —— 系统现在靠什么在撑着？什么时候到期？到期会怎样？
- **【五】外部依赖状态** —— 运营商 / 云服务商 / 第三方，现在有没有异常或公告？

---

## 三条铁律

1. **现象和判断分开写。** 现象是事实（连接数归零），判断是假设（链路断了）。混在一起，假设就变成了事实。
2. **"恢复"必须说清是哪一层。** 告警消失 ≠ 业务可用 ≠ 根因消除。
3. **必须写"我还不确定什么"。** 未知项比已知项更重要，它决定接班人往哪儿看。

## 说明

- 表格里的示例数据**全部是虚构的通用场景**，不含任何真实主机名、IP、业务名称。

- 交接单不是给别人定的规矩，是先用来补自己记性的。先自己填两周，再说别的。
